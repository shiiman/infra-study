# 実践テスト 試験2 採点基準

**100点満点。模範解答は `1. question1/` 〜 `4. question4/` を参照。**

---

## 採点の進め方

1. 受講者のブランチ(`exam/[名前]`)をチェックアウトする
2. コードを読んで、下記の配点表で加点する
3. 実物(ブラウザで `Congratulation!!`)を確認する

> **★ コードと実物の両方を見ること。**
> `apply` が通っていなくてもコードが正しければ部分点が付く。
> 逆に、`0.0.0.0/0` を開けて動かしただけなら減点する。

---

## 問1. ネットワーク(25点)

| 項目 | 配点 | 判定 |
|---|---|---|
| VPC を作っている | 5 | `google_compute_network` がある |
| `auto_create_subnetworks = false` | 5 | **これが無いと全リージョンにサブネットができる** |
| public / private の2サブネット | 5 | CIDR も指定どおりか |
| Cloud Router + Cloud NAT | 7 | 両方ないと点にならない |
| IAP からの SSH 許可 | 3 | `35.235.240.0/20` から22番 |

**よくある誤り**

- `auto_create_subnetworks` を書き忘れる → 既定は `true`。全リージョンにサブネットができる
- Cloud NAT だけ作って Cloud Router を作らない → NAT は Router に紐づくので作れない
- IAP のレンジを `0.0.0.0/0` にする → **-2点**

## 問2. VM 2台(25点)

| 項目 | 配点 | 判定 |
|---|---|---|
| VM が2台ある | 6 | `count = 2` でも2ブロック書いても可 |
| private サブネットにある | 5 | `subnetwork` が private を指しているか |
| 外部IPを持っていない | 5 | **`access_config` を書いていないこと** |
| イメージ・マシンタイプが指定どおり | 3 | `debian-cloud/debian-12` / `e2-medium` |
| ネットワークタグ | 3 | `[名前]-web` |
| 起動スクリプト | 3 | 指定どおり入っているか |

**よくある誤り**

- `access_config {}` を書いてしまう → 外部IPが付く。**-5点**
- タグ名を間違える → 問4のFirewallが効かなくなる。ここでは減点しないが、問4で響く
- サービスアカウントを指定していない → **減点しない**(問題文で求めていない)

## 問3. ロードバランサ(30点)

| 項目 | 配点 | 判定 |
|---|---|---|
| インスタンスグループ | 5 | 2台とも `instances` に入っているか |
| `named_port`(http/80) | 4 | **無いとバックエンドサービスがポートを解決できない** |
| ヘルスチェック | 5 | HTTP・80番・`/` |
| バックエンドサービス | 5 | ヘルスチェックとインスタンスグループを繋いでいるか |
| URLマップ | 3 | |
| ターゲットHTTPプロキシ | 3 | |
| グローバルIP + 転送ルール | 5 | IPを予約して転送ルールに渡しているか |

**よくある誤り**

- `named_port` を忘れる → apply は通るが疎通しない。**-4点**
- HTTPS で作ろうとして証明書待ちで時間切れ → 問題文で HTTP を指定している。
  HTTPSで作って動いていれば**満点にしてよい**(要件は満たしている)
- インスタンスグループに1台しか入れていない → **-3点**
- リージョン内部LBを作ってしまう → グローバル外部LBを求めている。**-10点**

## 問4. 通信を通す(20点)

| 項目 | 配点 | 判定 |
|---|---|---|
| Firewall ルールを作っている | 5 | |
| `130.211.0.0/22` が入っている | 5 | |
| `35.191.0.0/16` が入っている | 5 | **2つとも必要** |
| ポート80が開いている | 3 | |
| `target_tags` が問2のタグと一致 | 2 | |

**よくある誤り**

- `source_ranges = ["0.0.0.0/0"]` → 通るが**-10点**。
  「LB経由という前提が崩れる」ことを解説で説明する
- 片方のレンジだけ → 疎通しない。**-5点**
- タグ名がずれている → ルールはできるが通らない。**-2点**

## 実物確認(加点なし・減点あり)

| 状態 | 扱い |
|---|---|
| ブラウザで `Congratulation!!` が見える | **合格** |
| 503 が返る | Firewall かヘルスチェックを疑う |
| 502 が返る | VM側で nginx が上がっていない。起動スクリプトか NAT を疑う |
| 繋がらない | 転送ルールかIPを疑う |

> **503 と 502 の違い**
> - **503** = 健全なバックエンドが無い(Firewall / ヘルスチェック)
> - **502** = バックエンドが変な応答を返した(アプリ側)
>
> 第3回の検証で実際に出たのは **503** でした。解説で触れると理解が深まります。

---

## 部分点の考え方

- **apply が通っていなくても、コードが正しければ加点する。**
  時間切れで `apply` できなかっただけの人を落とさないため
- **動いているが方法が正しくない場合は減点する。**
  `0.0.0.0/0` がその代表
- 模範解答と書き方が違っても、**要件を満たしていれば満点**
  (`count` でも `for_each` でも2ブロック並べても可)
