# 実践テスト 試験2(Terraform 実技)

**制限時間 60分 / 4問 / 100点**

---

## ルール

**やってよいこと**

- ブラウザで何を調べてもよい(公式ドキュメント / 検索 / 過去の勉強会資料)
- 過去の自分のコードを見てもよい
- `terraform apply` を何度やり直してもよい

**やってはいけないこと**

- **module を読み込むこと**(`module "before"` のようなことをしない)
- **他人のコードを見ること**
- 他人に聞くこと

---

## 提出方法

提出用リポジトリの **自分の名前のブランチ**に push してください。

```
git clone https://github.com/[org]/[提出用リポジトリ].git
cd [提出用リポジトリ]
git checkout -b exam/[自分の名前]

# ここで作業

git add .
git commit -m "実践テスト"
git push origin exam/[自分の名前]
```

**時間内に push されたものだけを採点します。**
途中でも構わないので、**残り5分になったら必ず一度 push してください。**

---

## 前提

- 作業ディレクトリは1つ。4問は**続き物**です
- 問1で作ったものを問2で使い、問2で作ったものを問3で使います
- リソース名は指定がある場合を除き `[自分の名前]-` を先頭に付けてください
- リージョンは `asia-northeast1`、ゾーンは `asia-northeast1-a` を使ってください

---

## 問1. ネットワークを作る(25点)

次の条件でネットワークを作ってください。

| 条件 | 内容 |
|---|---|
| VPC | 名前 `[自分の名前]-vpc`。**サブネットは自動作成しない** |
| サブネット | 2つ。`[自分の名前]-public-subnet`(172.16.0.0/24)と `[自分の名前]-private-subnet`(172.16.10.0/24) |
| 外向きの経路 | private サブネットのVMが**インターネットに出られる**ようにすること |
| SSH | IAP から private サブネットのVMに SSH できるようにすること |

> **ヒント**: 「外部IPを持たないVMがインターネットに出る」ために何が要るかは第2回でやりました。
> ここができていないと、問2以降が動きません。

---

## 問2. VMを2台作る(25点)

次の条件で VM を作ってください。

| 条件 | 内容 |
|---|---|
| 台数 | 2台。名前は `[自分の名前]-web1` と `[自分の名前]-web2` |
| 配置 | **private サブネット** |
| 外部IP | **持たせないこと** |
| イメージ | `debian-cloud/debian-12` |
| マシンタイプ | `e2-medium` |
| ネットワークタグ | `[自分の名前]-web` |
| 起動スクリプト | 下記をそのまま使うこと |

```bash
#!/bin/bash
apt-get update
apt-get install -y nginx
echo "Congratulation!!" > /var/www/html/index.html
systemctl restart nginx
```

> **ヒント**: 起動スクリプトは `metadata_startup_script` に書きます。
> このスクリプトは apt-get するので、問1が正しくできていないと失敗します。

---

## 問3. ロードバランサを作る(30点)

2台のVMに **HTTP(80番)** で振り分けるロードバランサを作ってください。

| 条件 | 内容 |
|---|---|
| 種類 | グローバル外部アプリケーションロードバランサ |
| プロトコル | **HTTP**(HTTPSではない) |
| IPアドレス | グローバルIPを予約して使うこと |
| バックエンド | 問2で作った2台**とも**含めること |
| ヘルスチェック | HTTP の80番、パスは `/` |

出力に、ロードバランサのIPアドレスを出してください。

```hcl
output "lb_ip" { ... }
```

> **ヒント**: 第3回でやったとおり、ロードバランサは部品が多いです。
> 「VMを直接は見ない」ことを思い出してください。
>
> **HTTPS ではなく HTTP** で作ってください。
> 証明書の発行に10分近くかかり、試験時間に収まりません。

---

## 問4. 通信を通す(20点)

問3まで正しく作っても、ブラウザで開くと **503** が返るはずです。

原因を考えて、**ロードバランサからVMへの通信が通るように**してください。

**合格条件**

```
http://[ロードバランサのIP]/
```

をブラウザで開いて **`Congratulation!!`** が表示されること。

> **ヒント**: ロードバランサは VPC の**外**にいます。第3回 S32 でやりました。
>
> `0.0.0.0/0` を開ければ通りますが、それは正解ではありません。

---

## 提出前チェックリスト

- [ ] `terraform apply` が最後まで通る
- [ ] ブラウザで `Congratulation!!` が見える
- [ ] `terraform output lb_ip` でIPが出る
- [ ] コードを push した
- [ ] **`terraform destroy` はまだしない**(採点で実物を確認します)

---

## 採点が終わったら

**必ず `terraform destroy` してください。**

```
terraform destroy
```

VMが2台動いたままになるので、忘れると課金が続きます。
